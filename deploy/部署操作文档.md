# RAGFlow Enterprise 部署指南

项目支持 Docker 部署，并提供两套独立入口。两套部署共用业务代码和镜像构建文件，但运行拓扑、安全要求和资源规模不同，因此脚本应当分开，不能把笔记本的本地配置直接用于生产服务器。

| 场景 | 笔记本部署 | 企业服务器部署 |
| --- | --- | --- |
| 应用进程 | 单个 API 容器，内置前端 | API、Celery Worker、Celery Beat |
| 元数据 | SQLite | PostgreSQL 16 |
| 向量库 | 嵌入式 Chroma | Chroma HTTP Server |
| 文件存储 | Docker 本地卷 | MinIO |
| 缓存/任务 | 内存缓存、进程内任务 | Redis、Celery |
| 模型 | 宿主机 Ollama，或手动改为远程模型 | 企业模型网关或其他 OpenAI-compatible 服务 |
| 适用范围 | 演示、开发、单人试用 | 多用户、共享知识库、持续运行 |

## 一、企业服务器需要修改哪些文件

### 必须修改：`deploy/enterprise/.env`

首次执行脚本会由 `.env.example` 生成 `.env` 并停止启动。管理员需要填写：

- PostgreSQL、MinIO、JWT 和初始管理员的强密码；
- 回答模型的模型名、Base URL、API Key；
- Embedding 模型的模型名、Base URL、API Key；
- 对外访问域名 `CORS_ORIGINS`；
- HTTPS 场景保持 `COOKIE_SECURE=true`；临时使用 HTTP 验证时才设为 `false`；
- 根据 CPU、内存和模型吞吐调整 `WORKER_CONCURRENCY`。

`.env` 含密钥，已被 Git 忽略，不应提交到仓库。初始管理员只在用户表为空时创建；数据库已经初始化后，修改 `INITIAL_ADMIN_PASSWORD` 不会重置原账号密码。

### 通常不需要修改：Compose 和镜像文件

- `deploy/enterprise/docker-compose.yml`：现有拓扑可直接启动。只有接入外部 PostgreSQL/Redis/Chroma/MinIO、改变端口、拆分主机、限制 CPU/内存或增加副本时才需要调整。生产环境建议新增 Compose override 文件，避免直接改基础文件。
- `Dockerfile.enterprise`：只有使用企业内部镜像仓库、内部 CA 证书、Python/npm 私服或增加系统解析工具时才需要修改。
- Python/Vue 业务代码：正常部署不需要修改。只有新增模型协议、存储适配器、鉴权方式时才属于代码改造。

### 企业服务器启动

前置条件：64 位 Linux、Docker Engine、Docker Compose v2；建议至少 8 核 CPU、16 GB 内存和 100 GB 可扩展磁盘。模型不包含在当前 Compose 中，应准备企业模型网关或独立模型服务。

```bash
bash deploy/enterprise/deploy.sh up
```

第一次执行会创建 `deploy/enterprise/.env` 并提示填写；填写完成后再次运行。脚本会依次完成配置占位符检查、镜像构建、8 个服务启动、API 健康检查，以及数据库/缓存/对象存储/向量库/模型连通性验证。

常用命令：

```bash
bash deploy/enterprise/deploy.sh status
bash deploy/enterprise/deploy.sh logs
bash deploy/enterprise/deploy.sh validate
bash deploy/enterprise/deploy.sh restart
bash deploy/enterprise/deploy.sh down
```

`down` 只删除容器和网络，不删除命名卷。不要随意执行 `docker compose down -v`，否则会删除数据库、向量库和对象存储数据。

## 二、笔记本电脑怎么部署

前置条件：Windows 10/11、Docker Desktop（启用 Linux 容器）和 Ollama。建议至少 16 GB 内存；数据量较大或使用更大模型时建议 32 GB。

先在宿主机准备模型：

```powershell
ollama pull qwen3:4b
ollama pull nomic-embed-text-v2-moe
```

然后在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\laptop\deploy.ps1 -Action Up
```

脚本首次运行会自动创建 `deploy/laptop/.env`，生成随机 JWT 密钥和管理员密码，并打印一次初始密码。启动成功后访问 `http://localhost:8080`。

笔记本通常不需要修改代码，只在以下情况编辑 `deploy/laptop/.env`：

- 8080 端口被占用时修改 `APP_PORT`；
- 更换 Ollama 模型时修改 `OLLAMA_LLM_MODEL` 或 `EMBEDDING_MODEL`；
- 不使用 Ollama 时，将模型 Provider、Base URL、模型名和 API Key 改为远程服务配置；
- 确实需要本地 BGE 重排模型且内存足够时，将 `RERANKER_PROVIDER` 改为 `bge`。

常用命令：

```powershell
.\deploy\laptop\deploy.ps1 -Action Status
.\deploy\laptop\deploy.ps1 -Action Logs
.\deploy\laptop\deploy.ps1 -Action Validate
.\deploy\laptop\deploy.ps1 -Action Restart
.\deploy\laptop\deploy.ps1 -Action Down
```

数据保存在 Docker 命名卷 `ragflow-laptop-data`，重启或执行 `Down` 不会丢失。项目目前没有提供“本地 SQLite/嵌入式 Chroma到企业 PostgreSQL/Chroma HTTP”的自动迁移工具，因此正式环境应重新导入和构建知识库，不要直接复制笔记本数据目录。

## 三、生产上线前还要补齐什么

Compose 能完成应用部署，但生产上线还应由基础设施团队补齐：

1. 在 API 前增加 Nginx、Traefik 或企业 Ingress，配置 HTTPS、证书和请求体大小限制；只开放 80/443，不直接暴露 PostgreSQL、Redis、Chroma 和 MinIO。
2. 将 `.env` 密钥迁移到 Docker Secrets、Vault、Kubernetes Secret 或企业密钥平台，并定期轮换。
3. 为 PostgreSQL、MinIO、Chroma 配置备份、恢复演练、容量告警和独立磁盘；固定经过验证的 MinIO 镜像版本，避免长期使用 `latest`。
4. 接入日志采集、指标、链路追踪和告警；对模型网关设置并发、超时、配额和降级策略。
5. 上线前执行 `deploy.sh validate`，再做上传、索引、检索、引用和权限隔离的端到端验收。
