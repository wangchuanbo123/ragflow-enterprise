# 当前实现状态

> 检查日期：2026-07-30  
> 本文记录实际代码和本机数据状态，不等同于目标实施方案。

## 1. 当前结论

索引、图谱、运行可靠性和评估缺陷已经完成代码修复及自动化测试：

1. 全量重建会处理 `added`、`modified` 和 `unchanged` 的全部磁盘文档。
2. 影子 collection 全部成功并通过数量、ID 校验后才切换。
3. 单文件更新失败时保留旧 SQLite Chunk 和旧向量。
4. `failed` 或带索引错误的文档会重新进入 `modified`。
5. readiness 校验活动 collection 的向量数量和完整 Chunk ID 集合。
6. 图谱实体支持“问题包含实体名”、反向包含和别名匹配。
7. RRF 会合并同一 Chunk 的 `graph_facts`、图谱分数和检索通道。
8. 上传预生成的 `document_id` 会写入文档表、任务项并传给 Worker。
9. 分批向量写入中途失败会清理已经写入的新向量。
10. 向量删除失败不再被吞掉，任务会明确失败。
11. Runtime、Compiled LangGraph 和 BM25 会根据索引状态跨进程刷新。
12. 不兼容 collection 的回滚会因完整 Chunk ID 集不匹配而被拒绝。
13. `/ask` 已要求登录，全部问答入口接入统一并发限制和 Provider 超时。
14. Index Worker readiness 会检查真实线程状态，应用退出时会优雅停止 Worker。
15. 图谱 Schema 版本、低置信度过滤和单次 LLM 批量抽取已经实现。
16. 上传会限制读取大小、拒绝不支持的类型并复用重复内容的原始路径。
17. 旧向量清理失败会记录文档错误；下一次同步会从 Chroma 按
    `document_id` 反查并清除遗留向量。

评估脚本也已支持把 Windows 绝对路径、`data/docs/...` 和相对路径统一为
`data/docs` 下的相对路径。

## 2. 模型配置

问答、问题改写和知识图谱抽取复用同一个 Provider：

```text
ZhipuLLMProvider
model = glm-5.2
```

Embedding 仍为 Ollama `nomic-embed-text-v2-moe`，Reranker 仍为本地
`BAAI/bge-reranker-base`。Embedding 已改为 Ollama `/api/embed` 批量请求，
不再逐个 Chunk 调用旧接口。

## 4. 已验证行为

自动化测试已经覆盖：

- unchanged 文档会进入全量重建。
- 全量重建写入失败不会切换活动 collection。
- 单文件 Embedding 失败保留旧 Chunk 和向量。
- 失败文档会重新分类。
- readiness 能发现数量不一致。
- 上传 ID 在文档和任务之间保持一致。
- 图谱自然语言实体匹配。
- RRF 合并图谱事实。
- Windows 绝对来源路径归一化。
- Ollama Embedding 使用一次批量请求处理多个文本。
- 分批向量写入失败清理已写批次。
- 旧向量删除失败后可在下一次同步自愈。
- 不兼容 collection 回滚被拒绝。
- 图谱批量抽取只调用一次 LLM。
- 图谱 Schema 变化自动重抽取并过滤低置信度关系。
- 未登录用户不能调用 `/ask`。

## 6. 后续执行顺序

```powershell
# 1. 完整影子重建；中途终止不会切换旧索引
python -m scripts.ingest_documents --rebuild --yes

# 2. 检查 collection 和 readiness
python -m scripts.ingest_documents --list-collections
# 浏览器访问 http://127.0.0.1:8000/api/v1/ready

# 3. 重新运行评估
python -m scripts.evaluate_rag --mode retrieval --split tuning --label rebuilt
python -m scripts.evaluate_rag --mode retrieval --split holdout --label final

# 4. 索引一致后再构建图谱；该步骤会调用 GLM API
python -m scripts.ingest_documents --graph-only
```

重建过程使用新的影子 collection。只有全部文件成功、向量数量等于 3,880
且向量 ID 与待提交 SQLite Chunk ID 完全一致时，才会原子替换 SQLite Chunk
并切换活动指针。旧活动 collection 默认保留作为备份；由于 SQLite 当前只保存
一代 Chunk，只有 Chunk ID 与当前 SQLite 完全一致时才允许直接回滚，否则必须
重新构建该版本。

## 7. LangGraph 范围

当前五个节点保持不变：

```text
rewrite -> retrieve -> rerank -> build_context -> generate
```

`/ask` 使用 compiled LangGraph；Web 同步和 SSE 仍由 `RAGService` 手工调用
同一组节点函数。知识图谱是 `retrieve` 内部第三条检索通道，不是独立节点。
